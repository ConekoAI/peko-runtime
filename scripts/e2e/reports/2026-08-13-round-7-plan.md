# Round 7 (revised): delete the chapter concept, stable-id paging, restore `compact`, fix tool-surface drift

> Revision of the 2026-08-13 draft after fact-check review. Corrections
> from the review are baked in: crate paths (`peko_core`, not
> `peko_runtime`), verified line numbers, corrected premises (cache.rs
> already implements `branch_session`/`set_archived`; `SessionManager`
> has no `request_compaction`; `trigger` is load-bearing for the spawn
> depth check), a full paging spec, and the missing files/tests added
> to scope.

## Context

PR #353 (WS4 implicit session management, 2026-08-11) demoted 6
lifecycle actions from the `session` tool (`new` / `resume` / `branch`
/ `archive` / `unarchive` / `compact`). Round-5 field tests had shown
the model misusing `compact` mid-task and `new`/`resume` interrupting
tool loops. The audit at
`scripts/e2e/reports/2026-08-13-session-agent-tool-audit.md` flagged
the resulting drift: AGENT.md still advertised "12 actions",
`err_self_mutation` told the model to call demoted actions, and the
description omitted the tool surface the model actually has.

Design intent:

1. **The principal's root session is continuous**, owned by the
   engine. The model never drives its lifecycle.
2. **Subagent sessions are disposable but persistent until disposed
   of.** The model genuinely needs to manage them: branch a fork,
   archive a finished run, unarchive to read it back, compact a long
   transcript before resuming. PR #353 wrongly demoted these.
3. **A "chapter" is a category error.** A session is one agent. The
   `#<timestamp>` suffix leaks storage mechanics into session identity.
4. **Paging is implicit storage**, separate from session identity.
   When a JSONL exceeds `rotate_bytes`, the file pages; the session id
   stays stable.

Tool boundary (restated honestly): `session` performs storage reads/
writes with no LLM involvement. `Agent` covers anything that causes
LLM work — immediately (`new`, `resume`) or deferred (`compact` flags
a session; the engine summarizes at the target's next run).

| Action | Tool |
|---|---|
| `status` `list` `history` `search` `rename` `delete` `branch` `archive` `unarchive` | session (9) |
| `new` `resume` `compact` | Agent (3) |

## Paging spec (replaces draft A.2 — the risk center, now explicit)

Session id `S` is stable for life. On-disk layout:

- `<S>.jsonl` — the current page (append target, always the newest).
- `<S>.1.jsonl` … `<S>.N.jsonl` — older pages, chronological by
  number (1 = oldest). Page numbers are discovered by scanning the
  sessions dir for `<S>.<n>.jsonl` and parsing `<n>` numerically —
  **no** `page_index` in the metadata controller (dropped from the
  draft; directory scan is sufficient and adds no persistence format).

Rotation flow (was: rename `live` → `live#ts` + re-key):

1. `append_event_with_rotation` (peko-rs/session/src/jsonl.rs:197)
   detects `current_size + line.len() > rotate_bytes` under the
   existing `FileLock` discipline and calls the sink as today.
2. `SessionManagerRotationSink::request_rotation`
   (peko-rs/session/src/manager.rs:2447) becomes **page-in-place**:
   compute `n = max(existing pages) + 1`, rename `<S>.jsonl` →
   `<S>.n.jsonl`, leave index entry and `transcript_file`
   (`<S>.jsonl`) untouched. No `rename_session_id`, no peer
   re-registration, no `chapter_id`. The peer/cache invalidation
   steps in the current sink body exist only because the id changed;
   with a stable id they are deleted (context-cache invalidation for
   `S` stays).
3. `RotationOutcome::Rotated { from, to }` becomes
   `RotationOutcome::Paged { session_id, page_n }`. Fix the backwards
   doc comment at jsonl.rs:48-50 while there.
4. **Delete the re-keying** in `Session::append_to_storage`
   (peko-rs/session/src/unified.rs:858-870: `self.id = to`). The
   session object keeps its original id forever; the append after a
   page goes to a fresh `<S>.jsonl`.

Read-path stitching (single chokepoint, transparent to all readers):

- Implement page discovery + stitching inside peko-session's event
  loading (`SessionStorage::load_events` / `load_normalized` in
  jsonl.rs:476+): read pages `1..=N` in numeric order, then the
  current page. This automatically covers `Session::load_history`,
  `Session::build_context` (unified.rs:884+ — the LLM context path),
  `SessionManagerRuntime::get_history`, and
  `SessionService::get_history`
  (peko-rs/core/src/common/services/session_service.rs:430-497). No
  caller changes needed.
- Page discovery helper: `fn pages_for(sessions_dir, id) -> Vec<u32>`
  (directory scan, numeric parse, sorted). Reused by delete/branch.

Mutation page-awareness:

- `delete_session`: remove `<S>.jsonl`, every `<S>.*.jsonl` page, and
  sidecars (`.index.json`, `.context.cache`).
- `branch_session`: copy all pages preserving relative names under
  the new id.
- `rename_session_id`: was only called by the chapter rotation sink.
  After this round it has no production caller — delete it (and its
  tests), or keep `#[allow(dead_code)]` only if a caller remains.
  Session `rename` (retitle) is title-only and unaffected.
- Boot sweep `rotate_oversized_sessions` (manager.rs:2509-2551):
  delete the `if id.contains('#') { continue; }` clause; page any
  oversized live JSONLs found.

Compaction interaction: verify the compaction orchestrator's
transcript reads go through `load_events`/`build_context` (then they
stitch for free). If any compaction path reads the raw file directly,
route it through the stitching loader. Confirm during implementation;
do not hand-roll a second read path.

  discovery on case-insensitive filesystems, and compaction reads
  must be verified against real multi-page sessions (unit tests +
  probe-no-chapter-suffix.sh).
- **Depth-limit dependency** on `trigger` is untouched (kept).
- **Model behavior**: 9 + 3 split with honest compact semantics.
- **InboxRegistry / steering keys**: stable ids mean no rekeying —
  strictly simpler than today (rotation no longer re-keys).
